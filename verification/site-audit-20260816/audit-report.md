# Suzuki Yuma Portfolio — UX / Accessibility Audit

- Date: 2026-08-16
- Surface: トップページ全体
- Viewports: Desktop 1440 × 900 / Mobile 390 × 844
- User goal: 人物・研究テーマを理解し、成果・活動・社会実装を確認して連絡する
- Capture: 現在の Live Server を独立した Chrome で直接読み込み、イントロ終了後に撮影

## Overall verdict

研究者としての専門性、本人写真、研究と社会実装の両立は明確で、暗色テーマも一貫している。一方、固定ヘッダーがアンカー移動先の見出しを隠すこと、動画の初期表示、活動実績の情報密度、連絡フォームのコントラストが、内容を読む段階での主な摩擦になっている。

## Steps

1. **Desktop / Home — 良好**  
   Evidence: [01-desktop-home.webp](01-desktop-home.webp)  
   氏名、肩書き、所属、研究概要、本人写真の順序は明快。研究概要は英文が長く、初見で価値を掴むまでの負荷はやや高い。

2. **Desktop / Gallery — 改善が必要**  
   Evidence: [02-desktop-gallery.webp](02-desktop-gallery.webp)  
   2本の動画は研究内容を直感的に伝える。一方、アンカー移動で見出しが固定ヘッダーに隠れ、動画は黒画面・読込中表示から始まる。静止ポスターと短い説明が必要。

3. **Desktop / Papers — おおむね良好**  
   Evidence: [03-desktop-papers.webp](03-desktop-papers.webp)  
   年・題名・会議名の構造は読みやすい。見出しが固定ヘッダーに隠れ、DOI、PDF、著者情報、発表種別など次の行動につながる情報がない。

4. **Desktop / Activities — 改善が必要**  
   Evidence: [04-desktop-activities.webp](04-desktop-activities.webp)  
   実績量は強い信頼材料。ただし2列配置は時系列の読み順が曖昧で、全件が同じ強さで並ぶため受賞・採択・主要展示が埋もれる。

5. **Desktop / Social Project — 良好**  
   Evidence: [05-desktop-social.webp](05-desktop-social.webp)  
   Humoniiのブランドと説明はまとまっている。説明文は長く、成果指標や代表的な実証・受賞をカード内で短く示す余地がある。見出し欠けも継続する。

6. **Desktop / Contact — 改善が必要**  
   Evidence: [06-desktop-contact.webp](06-desktop-contact.webp)  
   メール、所属、SNSが揃っている。フォームのボタン文字が暗色背景で読みにくく、入力してもサイト内で送信完了せずGmailへ移動するため、期待とのずれが起きやすい。

7. **Mobile / Home — 改善が必要**  
   Evidence: [07-mobile-home.webp](07-mobile-home.webp)  
   1列化は破綻していない。固定ヘッダーが3段近い高さを占め、本文の英文とCTAが縦に長く、最初の成果へ到達するまでのスクロール量が多い。

8. **Mobile / Activities — おおむね良好**  
   Evidence: [08-mobile-activities.webp](08-mobile-activities.webp)  
   1列の実績一覧はPCより読み順が明確。ただし件数が多く、年別グループ・主要実績の強調・折りたたみがないため長い。

9. **Mobile / Contact — 改善が必要**  
   Evidence: [09-mobile-contact.webp](09-mobile-contact.webp)  
   入力欄は画面幅に収まる。固定ヘッダーが大きく、主・副ボタンの文字コントラストが不足し、フォーム、所属、SNSの優先順位も弱い。

## Strengths

- 名前、写真、研究テーマ、社会実装が一画面で結びついている。
- ダークテーマ、余白、角丸、アクセント色の一貫性がある。
- `lang="ja"`、フォームの `label`、画像の代替テキスト、主要セクションの意味構造は用意されている。
- 動画は遅延読込、背景効果は低メモリ端末と `prefers-reduced-motion` を考慮している。

## Highest-impact recommendations

1. **アンカー位置を修正する**  
   `.section` と `.site-footer` に `scroll-margin-top` を設定し、モバイルでは固定ヘッダーをロゴ＋メニューボタン程度へ縮小する。

2. **連絡フォームの読みやすさと期待値を直す**  
   `.btn` に明示的な文字色とフォント継承を入れる。必須項目、入力エラー、送信先の説明を追加し、可能ならサイト内送信に変更する。

3. **動画にポスターと説明を付ける**  
   各動画へ明るい代表フレーム、1行の目的、本人の担当、成果、再生時間を表示する。初期状態を黒画面・スピナーにしない。

4. **イントロを訪問体験として制御する**  
   初回またはセッション1回だけ再生し、スキップ操作を付ける。`prefers-reduced-motion` では即時に本文へ移る。現在はイントロ自体には軽減設定がない。

5. **活動実績を編集する**  
   受賞・採択・主要展示を先に5件程度出し、残りを年別アコーディオンへ移す。PCも1列の時系列にすると読み順が安定する。

6. **論文を詳細情報へつなぐ**  
   DOI / PDF / プロジェクトページ、著者、本人の役割、査読区分を追加する。

7. **トップの説明を短く強くする**  
   英文の前に「何を研究し、誰にどんな価値を届けるか」を1〜2文で置き、主要成果の数値または受賞を短いハイライトとして示す。

8. **日英表記を整理する**  
   ナビゲーション、本文、フッターの言語方針を統一するか、明確なJA / EN切替を用意する。

## Accessibility risks and limits

- スクリーンショットとコードから、固定ヘッダーによる見出し欠け、極小の所属文字、フォームボタンの低コントラスト、モーション軽減時も残るイントロを確認した。
- 独自の `:focus-visible` はないため、キーボード利用時の見え方はブラウザ既定表示に依存する。
- フォーム項目に `required` がなく、エラー回復や完了状態は用意されていない。
- スクリーンリーダーでの読み上げ順、実機のタッチ操作、色コントラスト比の正式測定、低速回線での動画挙動は今回の画像監査だけでは未確認。
